# BindLink 键链

BindLink（键链）是一个 Windows 桌面工具，把一个 Minecraft 实例里的按键、选项、Mod 配置、地图路点、Voxy 与 Bobby 缓存迁移到另一个实例。换整合包、升级版本或拿到朋友的客户端时，不用再手动重设几十个按键。

## 下载

在 [Releases](https://github.com/CL-matt/mc-bindsync/releases) 页面下载最新版本的 `bindlink.exe`，无需安装，双击即可运行。

## 功能

- **实例发现**：自动扫描程序所在目录及其上级目录中的 `.minecraft`，也可以手动添加目录。识别 `versions/<名称>/` 下的版本隔离实例，并标注由 PCL2 创建的实例。
- **两种同步模式**：
  - 局部合并：只同步 `key_` 开头的按键条目，保留目标整合包的视距、FOV、画质和音量。
  - 全量覆写：以模板为准覆盖全部选项，`version`、窗口分辨率、音频设备、资源包列表、上次连接的服务器等与本机或目标实例绑定的条目保留原值。
- **Mod 配置**：读取 `mods/` 中 jar 的元数据（`fabric.mod.json`、`quilt.mod.json`、`META-INF/mods.toml`、`META-INF/neoforge.mods.toml`）识别已安装的 Mod，目前支持同步 Axiom 的按键配置。
- **地图与路点**：按单人存档名或服务器地址同步 Xaero 小地图与世界地图数据，只补充缺少的文件和更新过的文件，不删除目标已有的文件。
- **Voxy 与 Bobby 缓存**：按服务器迁移 Voxy 超远视距缓存和 Bobby 区块缓存，两者分别选择物理复制，或用 Junction 让多个实例共用同一份缓存，不占额外磁盘空间。
- **材质包**：复制目标缺少的材质包，或把两个实例的材质包合并到共享目录后用 Junction 共用。同名但内容不同的材质包会弹窗列出来源、大小和修改时间，由你决定保留哪个。
- **Axiom 蓝图**：复制目标缺少的蓝图，或在两个实例游戏版本相同时用 Junction 共用蓝图目录。工具会读取每个蓝图保存时的游戏版本，比目标实例新的蓝图不会被复制过去，避免旧版本加载时崩溃。
- **自动备份**：修改任何配置文件前先生成 `.bak` 备份。

## 使用说明

### 准备

1. 关闭所有正在运行的 Minecraft。游戏运行时会占用 Voxy 与 Bobby 缓存文件，工具检测到占用时会跳过对应缓存，材质包同理；游戏也可能在退出时覆盖刚迁移的 `options.txt`。
2. 目标实例至少要启动过一次游戏，生成自己的 `options.txt`。目标没有 `options.txt` 时，工具会跳过选项同步并在日志中提示。
3. 把 `bindlink.exe` 放到 PCL 程序所在的文件夹（与 `.minecraft` 同级），启动时会自动发现其中的实例。放在其他位置也可以，启动后用"添加目录…"选择 `.minecraft`、它的上级目录或某个版本目录。

### 迁移步骤

界面左侧是按"实例 / 固定配置 / 按键与配置 / 地图与缓存 / 材质包与蓝图"分组的选项，右侧是日志，两者之间的分隔线可以拖动调整宽度。

1. **选择实例**：在"模板实例"中选择配置好的旧实例，在"目标实例"中选择要写入的新实例。鼠标悬停在选项上可以看到实例的完整路径。实例名后的"隔离"表示版本隔离实例，"根目录"表示 `.minecraft` 本身的共享配置。
2. **（可选）使用固定配置**：左侧"固定配置"卡片中的按钮可以一次填好下面的选项，填好后仍可逐项修改：
   - 洛林：局部合并，同步地图与路点，Voxy 与 Bobby 缓存物理复制。
   - neko喵喵喵：全量覆写，同步地图与路点，Voxy 与 Bobby 缓存用 Junction 指向共享目录。点击后还需要选择共享目录。
   - 两个固定配置都会把 Axiom 蓝图设为"不处理"，不改动材质包的选项。
3. **选择同步内容**：
   - "按键与选项（options.txt）"和"Mod 独立配置"按"同步模式"执行。只想迁移按键时选"局部合并"，想让新实例的画面、声音等设置和旧实例完全一致时选"全量覆写"。
   - "地图与路点（Xaero）"会把模板中所有世界和服务器的地图数据同步到目标。
4. **分别选择 Voxy 缓存与 Bobby 缓存的处理方式**：
   - 不处理：保持目标现状。
   - 物理复制：迁移后准备删除旧实例时选用。缓存通常有数百 MB 到数 GB，复制需要一段时间。
   - Junction 指向源实例：旧实例还要继续玩时选用，两个实例共用同一份缓存。删除旧实例后链接会失效。
   - Junction 指向共享目录：同一个服务器的整合包反复更新时选用。点击"选择共享目录…"指定一个长期保存缓存的文件夹，工具会把旧实例的缓存移到其中的 `voxy\` 或 `bobby\` 子目录，旧实例和新实例都链接到这里。两种缓存共用同一个共享目录。以后整合包再更新，只需对新版本再执行一次。
5. **选择材质包的处理方式**（固定配置不会修改这一项）：
   - 不处理：保持目标现状。
   - 复制缺少的材质包：把旧实例有、新实例没有的材质包复制过去，新实例自带的材质包保持不变。
   - Junction 指向共享目录（同步启用列表）：把旧实例和新实例的材质包合并到共享目录下的 `resourcepacks\`，两个实例都链接到这里，并把旧实例已启用的材质包列表写入新实例。新实例中与共享目录相同或你选择不采用的材质包，会整体保留在 `resourcepacks.<时间戳>.bak`。
   - 遇到同名但内容不同的材质包时会弹出窗口，逐个列出双方来自哪个实例（或共享目录）、大小和修改时间，选择"保留现有"或"使用新版本"后点"确定"，迁移才会继续。
6. **选择 Axiom 蓝图的处理方式**（只在新实例装了 Axiom 时生效）：
   - 不处理：保持目标现状。
   - 复制缺少的蓝图：把旧实例有、新实例没有的蓝图复制过去。保存时游戏版本比新实例高的蓝图会被跳过并在日志中列出，例如 26.3 保存的蓝图不会被放进 26.2 实例，因为加载它会让游戏崩溃。新复制的蓝图会追加到 Axiom 蓝图列表的末尾。新实例需要启动过一次游戏，工具才能读到它的版本。
   - Junction 指向共享目录（仅限两个实例版本相同）：把两个实例的蓝图合并到共享目录下的 `axiom-blueprints\`，之后在任一实例保存的蓝图，另一个实例都能看到。两个实例游戏版本不同时会拒绝执行。共享后如果升级了其中一个实例的游戏版本，请先删除它的蓝图链接，否则在新版本保存的蓝图会让旧版本实例崩溃。
   - 同名冲突的弹窗与材质包相同，另外会显示双方蓝图保存时的数据版本号。
7. 点击窗口右下角的"开始迁移"，在右侧日志区查看每一步的结果。日志按级别着色：灰色表示跳过，绿色表示已写入，黄色表示单项警告，红色表示步骤失败；日志区标题旁会统计警告和失败的条数。底部状态栏显示本次迁移是否完成。

使用 Junction 时，共用同一份缓存的多个实例不能同时运行。

### 备份与恢复

| 内容 | 备份位置 | 恢复方法 |
| --- | --- | --- |
| `options.txt`、Mod 配置文件 | 同目录下的 `<文件名>.bak`（第一次修改前的原始文件，永久保留）和 `<文件名>.<时间戳>.bak`（之后每次修改前的版本，保留最近 5 份） | 删除当前文件，把需要的备份文件改回原文件名 |
| Voxy 与 Bobby 缓存 | 目标原有的缓存目录被重命名为 `<目录名>.<时间戳>.bak` | 删除新建的链接或目录后，把备份目录改回原名 |
| 材质包 | 被替换的版本移入 `resourcepacks.bak\`（复制模式在新实例的游戏目录下，共享模式在共享目录下）；共享模式下未并入的原有材质包保留在 `resourcepacks.<时间戳>.bak` | 把备份移回 `resourcepacks\` 并去掉名称末尾的时间戳 |
| Axiom 蓝图 | 被替换的版本移入 `config\axiom\blueprints.bak\`（复制模式）或共享目录下的 `axiom-blueprints.bak\`（共享模式）；共享模式下未并入的原有文件保留在 `config\axiom\blueprints.<时间戳>.bak`；蓝图排序文件按配置文件规则备份 | 把备份移回 `blueprints\` 并去掉名称末尾的时间戳 |
| 地图与路点 | 不逐个备份，执行前在日志中列出将被覆盖的文件 | 需要时请自行提前备份 `xaero` 目录 |

删除 Junction 时请在命令提示符中执行 `rmdir "<链接路径>"`，该命令只删除链接本身，不会删除链接指向的缓存。

### 限制

- 暂不支持 HMCL 的启动器标注与 JourneyMap 地图同步，计划见 [todolist.md](todolist.md)。
- 模板与目标分处 1.13 前后时，两者的按键格式不兼容，工具会跳过全部按键条目，只迁移其他选项。
- 损坏的 jar 或不规范的 Mod 元数据会被跳过并记录在日志中，不影响其他 Mod 的识别。

## 从源码构建

需要 Rust 的 `x86_64-pc-windows-gnu` 工具链，以及提供 `dlltool` 与 `as` 的完整 MinGW-w64（例如 WinLibs），并把 MinGW-w64 的 `bin` 目录加入 PATH。

```
cargo build --release
```

`.cargo/config.toml` 把构建产物目录设在 `<构建目录>`，其他机器上构建前请修改或删除该配置。构建产物为 `target/release/bindlink.exe`。运行 `cargo test` 执行单元测试。

| `mem.md` | 项目设计与同步规则 |
| `logos/` | 软件标志 `bindlink.svg` 与其 256 px PNG 版本（窗口图标与标题栏使用），以及 LorianTool 图标；PNG 编译时嵌入程序 |
